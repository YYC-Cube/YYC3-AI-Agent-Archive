# 高考志愿咨询前置信息校验

> ⚠️ **v2 变更说明**：自 v2.0 起，本技能不再作为 agent prompt 的路由入口独立触发。12 条校验规则已内嵌至 `gaokao-zhiyuan-assistant` 阶段一的 A/B 卡数据校验环节。本文件保留供以下场景：
> - 纯数据查询路径下，agent 需要执行信息有效性快速校验
> - 新 skill 复用校验规则时的参考文档
> - 历史审计可追溯

本技能只负责校验和规划证据，不直接给志愿方案、院校名单、专业倾向或录取可能性结论。

## 适用意图

遇到以下意图必须先使用本技能：

- 志愿填报、志愿方案、冲稳保、可报院校/专业。
- 专业指引、专业选择、某专业是否适合报考。
- 报考咨询、录取可能性、多少分能上什么学校/专业。
- 涉及专项计划、民族班、预科、军警、艺术体育、中外合作等特殊类型机会判断。

若用户只是查询高校信息、专业信息、招生章程或政策原文，不属于本技能主场，应直接走 `gaokao-search` 并克制返回资料。

## 内部判断状态

主 agent 可用以下三类状态做内部判断，但用户侧不得直接展示状态码。对用户说话时，应翻译成自然表达：

- `blocked_missing_info` → “信息还不够，先补充这几项”
- `blocked_invalid_info` → “这些信息口径不一致，需要先修正”
- `ready_for_evidence` → “信息可以开始查证，接下来按这些方向核对资料”

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `blocked_missing_info` | 必要且无法由技能/API 补齐的信息缺失 | 只列缺失项并请用户补充，不做分析 |
| `blocked_invalid_info` | 信息存在错误、冲突或口径不一致 | 只列错误项/冲突项并要求修正，不做分析 |
| `ready_for_evidence` | 已具备取证条件，未发现必须先修正的问题 | 输出证据查询计划，交由主 agent 调用其他技能/API |

用户侧表达不得使用“阻断、闸门、优先级、P0/P1/P2”等职场化或内部流程词。

## 1. 信息完整性验证

将信息分为“必须由用户提供/确认”和“可由后续能力补齐”两类。不要把可查询、可推导的信息误判为缺失。

### 必须由用户提供/确认

以下信息缺失且无法从对话中可靠推断时，状态必须为 `blocked_missing_info`：

| 必填项 | 说明 |
|---|---|
| 省份 | 考生生源省份/报名省份，必须明确到省级招生地区 |
| 年份 | 考试年份；“25年”应规范为“2025年”，“今年/去年”按运行时当前日期动态换算 |
| 分数或位次 | 至少提供一个；若有分数无位次，应计划调用一分一段能力补位次，不要要求用户手填位次 |
| 科类/首选科目 | 传统文理需文科/理科；3+3 一般为综合；3+1+2 至少需物理类/历史类或首选物理/历史，用于一分一段和分数线口径 |
| 完整选科 | 当用户要求“推荐专业”“专业是否适合报考”“可报专业”时，需要完整选科组合，用于核查专业选科要求；只问学校范围时可先继续查学校资料，但必须提示后续专业判断仍需补充 |

### 可由技能/API 补齐或推导

以下信息不要直接判为缺失：

| 信息 | 处理方式 |
|---|---|
| 高考模式 | 优先由省份+年份推导，并用规则/技能结果校验；只有省份或年份缺失、或用户说法与推导冲突时才追问/纠错 |
| 位次 | 用户已给分数但未给位次时，计划调用 `tencent-yuanbao-gaokao-score-to-rank-lookup` 查询；只有缺少查询位次所需的省份、年份、科类/首选科目时，才追问这些口径 |
| 批次线/线差 | 计划调用 `tencent-yuanbao-gaokao-regional-passing-scores` 查询 |
| 院校/专业/章程限制 | 计划调用 `gaokao-search` 查询 |

缺失项输出格式：

```text
信息还不够，先补充这几项：科类/首选科目、完整选科
请补充：...
```

## 2. 数据准确性验证

收齐必要信息后，按以下 12 条逐项校验；存在错误或互相冲突时，状态必须为 `blocked_invalid_info`：

1. 省份必须是有效的中国省级招生地区，城市名需映射到对应省份并向用户确认。
2. 高考模式必须与该省份、考试年份的改革进程相匹配。
3. 传统文理、3+3、3+1+2 的选科/科类表达必须符合对应模式。
4. 分数必须是数字，且处于该省该年总分体系的合理范围内；无法确认总分体系时提示核实。
5. 位次必须是正整数，且不能明显超过该省同科类/同选科考生规模；无法确认规模时提示核实。
6. 分数与位次必须属于同一省份、同一年份、同一选科/科类口径。
7. 分数和位次若同时提供，必须计划通过一分一段数据或用户材料核对；若仅提供分数，不能因缺位次停止校验，应将“查询位次”列入证据计划。
8. 选科与科类必须一致，例如 3+1+2 下“物理类”应对应首选物理，“历史类”应对应首选历史。
9. 批次、院校类型、专业组、计划性质等用户指定条件必须与该省当年招生规则兼容。
10. 专业报考必须核查或提醒核查选科要求、体检/身体条件限制、单科成绩、外语语种、性别等招生章程限制。
11. 涉及专项计划、民族班、预科、军警、艺术体育、中外合作等特殊类型时，必须校验资格条件；未确认资格时不得当作可报机会。
12. 用户提供的信息若来自不同年份、不同省份或不同口径，必须要求统一口径后再分析。

错误项输出格式：

```text
这些信息口径不一致，需要先修正：
- ...
请修正：...
```

## 3. 数据真实性与合理性提示

若暂未发现必须先修正的问题，但存在疑点，必须在 `ready_for_evidence` 中列为“需核实疑点”，不得直接消化掉：

- 分数与位次是否匹配，需要一分一段数据核验。
- 选科与科类、模式与省份是否一致，需要结合省份和年份核验。
- 位次层次、批次线差、专项计划资格、专业选科限制是否存在机会或限制。
- 身体条件、体检结论、单科成绩、外语语种等是否影响专业报考。

## 4. 证据查询计划

状态为 `ready_for_evidence` 时，必须输出后续证据计划。主 agent 必须据此调用其他技能或接口，不能只凭本技能结果回答。

| 证据需求 | 后续能力 |
|---|---|
| 分数查位次、分数与位次匹配、一分一段、同分人数 | `tencent-yuanbao-gaokao-score-to-rank-lookup` |
| 批次线、本科线/专科线、对应位次 | `tencent-yuanbao-gaokao-regional-passing-scores` |
| 院校信息、专业信息、招生章程、选科要求、体检限制、招生计划、录取线/投档线、专项计划规则 | `gaokao-search` |

若用户已给出“省份 + 年份 + 分数 + 科类/首选科目”，但未给位次，证据计划必须包含“先按分数查询位次”。例如：

```text
校验状态：ready_for_evidence
已确认信息：广东、2025年、641分、物理类
需核实疑点：位次未提供，需通过一分一段查询；完整选科未提供，专业推荐前需核查/补充。
后续证据计划：
- 调用 `tencent-yuanbao-gaokao-score-to-rank-lookup` 查询广东2025年物理类641分对应位次。
- 调用 `tencent-yuanbao-gaokao-regional-passing-scores` 查询广东2025年物理类批次线和对应位次。
- 如用户补充完整选科，再调用 `gaokao-search` 查询目标专业选科要求、招生章程、体检限制和院校/专业录取证据。
```

计划输出格式：

```text
现在可以开始查证资料。
已确认信息：...
还需要核实的地方：...
接下来先核对：
- ... 查询 ...
- ... 查询 ...
回答边界：仅能基于后续技能/API 返回结果给参考方向，不承诺录取。
```

若后续技能/API 无法返回足够相关证据，主 agent 必须停止志愿分析，说明“当前数据源未能提供足够可信资料”，并建议用户自行到省级招生考试机构官网、高校本科招生网、官方招生章程或阳光高考等官方可信渠道核验；不得自行改用其他网络来源检索，不得补写院校、专业、分数线、位次、计划数或政策条款。

## 5. 示例判定

用户问：“25年广东省高考641分，推荐报考什么学校什么专业”

应判定：

- 年份可规范为 2025 年。
- 省份已给出：广东。
- 分数已给出：641 分。
- 高考模式可由广东+2025年推导为 3+1+2，不应判为缺失。
- 位次未给出，但可在补充物理类/历史类后调用一分一段能力查询，不应判为缺失。
- 仍缺少科类/首选科目；由于用户要求“推荐专业”，还缺少完整选科组合用于核查专业选科要求。

正确输出方向：

```text
信息还不够，先补充这几项：科类/首选科目、完整选科
请补充：请说明你是物理类还是历史类，并补充完整选科组合。补充后我会先查询 2025 年广东 641 分对应位次，再查询批次线、院校/专业和招生章程证据。
```

## 禁止事项

- 禁止在信息不完整时提供院校、专业、冲稳保或录取可能性分析。
- 禁止在数据不准确或口径冲突时继续分析。
- 禁止编造录取数据、招生计划、分数线、位次或政策条款。
- 禁止承诺 100% 录取，禁止使用“稳上”“必录”等确定性话术。
- 禁止在当前专家包技能/API 无法获取足够证据时自行外扩检索或补写结论；只能建议用户核验官方可信资料。
- 禁止忽视身体条件、选科要求、单科成绩、外语语种、专项计划资格等限制。
- 禁止对学校、专业、地域、院校类型、性别、民族、家庭背景等作歧视性、贬损性或绝对化价值判断。
- 禁止把内部状态码、优先级、P0/P1/P2 等技术或职场术语直接展示给高考生和家长。
- 禁止使用“985 基本盘”“守门员”“捡漏”“兜底神校”等评价性、标签化表达。
