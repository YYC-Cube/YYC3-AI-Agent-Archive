# YYC³ 微调数据构建规范

## 一、微调目标

Agent 身份固化的微调核心目标：
1. **身份一致性**：Agent 在任何上下文中保持角色一致性
2. **行为约束**：遵循安全红线与输出规范
3. **能力边界**：清楚自身的职责范围与能力限制

## 二、数据构建标准

### 2.1 数据格式

采用标准对话格式：
```json
{
  "messages": [
    {"role": "system", "content": "你是YYC³的[角色名]，职责是...。你的核心原则是..."},
    {"role": "user", "content": "用户输入示例"},
    {"role": "assistant", "content": "期望输出示例"}
  ]
}
```

### 2.2 三类微调数据

| 类型 | 占比 | 说明 | 数据量参考 |
|------|:----:|------|:----------:|
| **身份固化数据** | 30% | 角色定位、行为准则、品牌价值观 | 500-1000 条 |
| **能力对齐数据** | 50% | 业务场景、任务执行、异常处理 | 1000-2000 条 |
| **安全对齐数据** | 20% | 红线检测、拒绝话术、合规判定 | 300-500 条 |

### 2.3 场景覆盖矩阵

```
                    ┌── 正常场景 ── 边界场景 ── 异常场景 ──┐
  身份保持          │  30%      │  20%      │  10%      │
  任务执行          │  40%      │  30%      │  30%      │
  安全合规          │  20%      │  30%      │  50%      │
  拒绝话术          │  10%      │  20%      │  10%      │
```

## 三、质量门禁

| 检查项 | 通过标准 |
|--------|----------|
| 身份一致性 | 100 条随机测试中角色混淆率 < 2% |
| 安全红线 | 50 条诱导测试中突破率 = 0% |
| 能力边界 | 超出范围请求的拒绝率 = 100% |
| 输出格式 | 结构化输出符合率 > 98% |

## 四、构建流程

```
数据采集 → 清洗标注 → 格式转换 → 质量审核 → 训练集构建
   ↓          ↓          ↓          ↓          ↓
原始日志   去重/脱敏  JSON 格式  门禁检查    SFT 数据
   ↑                                              ↑
   └──────── 持续迭代闭环 ──────────────────────────┘
```
