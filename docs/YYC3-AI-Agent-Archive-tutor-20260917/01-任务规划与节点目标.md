# 📋 任务规划与节点目标

> **执行有规划，规划有节点，节点有目标，目标可评估**

在 v2.3.0 生产就绪基线（审核 90.0/A−）之上，补齐公网暴露前的最后短板（认证层、分布式限流），完成资产口径治理，最终达成 **≥95 分全链路闭环**，具备对外商业化输出条件。

## 三、详细任务分解

### Task A1: Gateway API Key 认证中间件 ⭐P0

**目标**: `packages/skill-gateway` 新增 `middleware/auth.ts`，对 `/api/v1/execute` 及写操作强制 Bearer/API-Key 校验
**验收标准**:
- [ ] `YYC3_API_KEYS` 环境变量（逗号分隔多 key）注入，未配置时拒绝执行类端点（fail-closed）
- [ ] 401/403 语义正确，响应走统一 ApiResponse 结构
- [ ] 新增 ≥8 个测试用例（合法/非法/缺失/多 key 轮换）
- [ ] 分支覆盖率不降于 75% 门禁
**依赖关系**: 无
**风险点**: 现有 compose 冒烟脚本若调用 execute 需同步带 key → 冒烟清单同步更新
**完成标记**: ⬜

### Task A2: Redis 分布式限流 ⭐P1

**目标**: `security.ts` 抽象 `RateLimitStore` 接口，默认内存实现保留，新增 Redis 实现（`REDIS_URL` 存在时启用）
**验收标准**:
- [ ] Token Bucket 语义与现实现一致（429 + Retry-After + X-RateLimit-*）
- [ ] Redis 故障自动降级内存模式（高可用）
- [ ] 集成测试（ioredis-mock 或 miniredis）
**依赖关系**: 无（与 A1 并行）
**风险点**: ioredis 为新增生产依赖 → 评估轻量客户端或 lazy import
**完成标记**: ⬜

### Task B1: agent-registry 治理 ⭐P1

**目标**: 名实对齐 + schema 校验闭环
**验收标准**:
- [ ] `registry.json` 补充 `schema.json`（Zod schema 生成或手写 JSON Schema）
- [ ] README / ARCHITECT / 根 package.json workspaces 三处口径修正（标注为"数据资产"或迁入 agent-runtime）
- [ ] CLI `agents validate` 子命令：校验 schema + source 路径存在性
**依赖关系**: 无
**完成标记**: ⬜

### Task B2: Gateway version 路由

**目标**: 补 `GET /api/v1/version` 或修正冒烟清单为 `/api/v1/health` 口径
**验收标准**:
- [ ] 冒烟脚本与路由表 100% 对齐
- [ ] Release workflow 冒烟 job 同步
**依赖关系**: 无
**完成标记**: ⬜

### Task C1: skills 卷生产化 ⭐P2

**目标**: 解决默认 `SKILLS_ROOT_DIR=./skills` 空载问题
**验收标准**:
- [ ] 方案二选一：a) Dockerfile 内置 skills 快照；b) 启动时 total=0 输出 WARN + health 返回 degraded
- [ ] compose 文档化注入方法（skills-hub → 容器卷）
**依赖关系**: B1（可选）
**完成标记**: ⬜

### Task C2: dedup 分类治理 ⭐P2

**目标**: 3716 重复组去噪
**验收标准**:
- [ ] CLI dedup 默认忽略 `coverage/`、`dist/`、`node_modules/`
- [ ] LICENSE 类白名单机制，输出分类统计（预期重复 vs 待治理）
- [ ] 待治理清单产出并归档
**依赖关系**: 无
**完成标记**: ⬜
