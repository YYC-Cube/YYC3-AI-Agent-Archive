# 📐 可复用技术与项目蓝图 — 全链路生产闭环

> **定位**：本文档是 YYC³ AI Agent Archive 的「技术资产说明书 + 复用手册 + 运维独立宣言」。
> 基于对全网同类项目的深度调研，提炼可复用模式，确保后期运维**不受上游约束**。

## 一、同类项目全景调研（2026 年 9 月实测）

### 1.1 对标项目矩阵

| 项目 | 定位 | 核心架构 | 优势 | 劣势（对我们的启示） |
| ------ | ------ | ---------- | ------ | --------------------- |
| **Dify** (LangGenius) | 可视化 LLM 平台（工作流/RAG/Agent/Prompt IDE/LLMOps） | 插件优先：LLM/工具/函数全为插件；Marketplace/GitHub/本地上传；workspace 级权限 | 上手快、生态大、自托管友好 | Apache-2.0 有 SaaS 限制条款；平台重、绑定其 Runtime |
| **Langflow** | 开发者向可视化编辑器 | 节点级代码可编辑 | 灵活度高于 Dify | 学习曲线陡；无统一资产市场 |
| **Flowise** | 轻量拖拽构建器 | Node.js + LangChain | 简单场景交付快 | 复杂场景能力不足 |
| **n8n** | 通用自动化 | 非 LLM 专用 | 连接器生态 | 非原生 Agent 语义 |
| **LangChain Hub / LlamaHub** | Prompt/组件托管 | 云注册表 + SDK 拉取 | 内容丰富 | 强绑定各自 SDK 版本 |
| **MCP Registry (官方)** | MCP 服务器元数据中心 | server.json + 反向 DNS 命名空间 + REST API + OpenAPI 规范 | 官方背书（Anthropic/GitHub/Microsoft）；namespace 验证 | **官方明确不支持自托管**，企业私有 MCP 须自建私有注册表 |
| **Agentregistry** | 开源 Agent 注册中心 | 单一真相源（SSOT）目录 | 活跃维护 | 尚无技能资产沙箱执行层 |
| **Anthropic Agent Skills (SKILL.md)** | 技能开放标准 | SKILL.md + YAML frontmatter + scripts/references 目录 | **已被 OpenAI Codex CLI / Cursor 跨平台采用**；Skills API 已 GA | 标准仍在演进 |

### 1.2 关键行业信号（调研结论）

1. **SKILL.md 已成为事实标准**（agentskills.io 规范，OpenAI/Cursor 均兼容）— 任何 Agent 资产平台必须以它为第一公民格式
2. **MCP Registry 官方不做自托管** → 企业私有化部署是**真空地带**，自建注册表（实现其 OpenAPI 规范）是明确蓝海
3. **插件化 + 市场化**（Dify 模式验证）是 Agent 平台的终局形态；但**资产安全执行层**（沙箱）是 Dify/Langflow 均薄弱的环节
4. **GitHub Actions 2026 安全路线图**：workflow 级依赖锁定（commit SHA 锁定）即将强制 — 所有 CI 引用须 pin SHA
5. **供应链攻击常态化**（2026 春季 OSS 事件）：pin-to-SHA、dependency review 门禁、package override kill switch 是三大防线

### 1.3 本项目的差异化优势（对标结论）

| 能力 | Dify | Langflow | MCP Registry | **YYC³ Archive** |
| ------ | :---: | :---: | :---: | :---: |
| 技能资产格式 | 插件包 | 节点 | server.json | **SKILL.md 原生（831 个，0 错误校验）** |
| 沙箱执行层 | ⚠️ 弱 | ⚠️ 弱 | ❌ 无 | ✅ **40+ 危险模式正则 + 三运行时隔离** |
| 私有注册表能力 | 部分 | ❌ | ❌ 官方不支持自托管 | ✅ **仓库即注册表（git-native）** |
| 认证与限流 | 平台内置 | 平台内置 | N/A | ✅ **API Key fail-closed + Redis/内存双模限流** |
| 全链路 CI/CD | ✅ | ✅ | N/A | ✅ **13 包门禁 + Docker 冒烟 + GHCR + Pages** |
| i18n 键级同步 | ✅ | ❌ | ❌ | ✅ **1597 键双向零缺失（脚本可复用）** |
| 运维独立性 | 中（平台耦合） | 中 | 低（官方不自托管） | **高（本蓝图核心）** |

> **一句话定位**：本项目 = 「SKILL.md 原生的 git-native 资产注册表 + 沙箱执行网关 + 全链路自动化」，恰好填补 MCP 官方注册表「不支持自托管」与 Dify 系「平台锁定」之间的生态空位。

## 二、可复用技术资产清单（可直接搬运）

以下组件均为本项目已验证实现，可整体复用于任何新项目：

### 2.1 工程基建层

| 资产 | 位置 | 复用方式 |
| ------ | ------ | ---------- |
| Turbo Monorepo 骨架 | `turbo.json` + `pnpm-workspace.yaml` | 复制后改包名；`test` 强制 `cache:false` 防假绿是关键细节 |
| 13 包统一 TS 配置 | `tsconfig.base.json` + 各包 tsconfig | strict + bundler resolution + NodeNext |
| 覆盖率门禁矩阵 | 各包 vitest.config.ts | 分支 ≥70%（i18n ≥80%），CI 强制 |
| 双注册源审计 | CI `pnpm audit --registry=https://registry.npmjs.org` | 规避镜像源无 audit 端点问题（npmmirror 404 实测） |
| 会话文档四件套 | `docs/{project}-{tutor}-{date}/00~03` | YYC³ 标准：审核/规划/日志/总结，跨会话可衔接 |

### 2.2 安全中间件层（`packages/skill-gateway/src/middleware/`）

| 资产 | 关键设计 | 复用要点 |
| ------ | ---------- | ---------- |
| **apiKeyAuth**（auth.ts） | `timingSafeEqual` 时序安全比较；Bearer/X-API-Key 双通道；**fail-closed**（未配置密钥 → 503 拒绝） | `write`/`all` 双模式；多 key 逗号分隔 env 注入 |
| **RateLimitStore**（rate-limit-store.ts） | 接口抽象：`MemoryStore`（零依赖兜底）+ `RedisStore`（Lua 原子 Token Bucket） | `enableOfflineQueue:false + retryStrategy:()=>null` 是 ioredis 快速失败的关键；连接失败自动降级内存 |
| securityHeaders | Helmet 式六大头 + 删除 Server 指纹 | 直接复用 |
| bodySizeLimit | Content-Length 前置校验 | 直接复用 |

### 2.3 资产治理层

| 资产 | 位置 | 复用方式 |
| ------ | ------ | ---------- |
| 注册表 JSON Schema 校验 | `packages/agent-registry/schema.json` + 校验脚本 | `id` 正则 / `category` 枚举 / `source` 路径存在性 / stats 一致性四维校验 |
| 技能三件套 CLI | `skills validate/stats/dedup` | 831 文件 0 错误；dedup 白名单机制（LICENSE 类预期重复） |
| i18n 键同步校验 | 根 scripts（zh/en 深度 diff） | 1597 键双向零缺失，任何多语言项目可复用 |

### 2.4 部署层

| 资产 | 位置 | 复用方式 |
| ------ | ------ | ---------- |
| Pages 自动部署 | `.github/workflows/pages.yml` | `paths: public/**` 触发 + `workflow_dispatch`；**官方 deploy-pages 链路**（非 branch-from-gh-pages 旧式） |
| Docker 三镜像矩阵 | `Dockerfile` + release.yml | 多 target 构建 + GHCR 推送 + **compose 冒烟 8 项 API 断言**后再推送 |
| 自定义域名绑定 | `public/CNAME` + Pages settings | DNS CNAME → github.io，仓库内 CNAME 文件落地 |

## 三、运维独立架构（不受上游约束）

> **核心原则**：上游是「可选加速器」，而非「生存依赖」。任何上游消失，系统仍可独立运行 ≥ 12 个月。

### 3.1 上游依赖面分析

| 上游 | 当前依赖 | 断供影响 | 独立性保障 |
| ------ | ---------- | ---------- | ----------- |
| Anthropic（SKILL.md 标准） | 技能格式约定 | 格式标准已有独立规范站（agentskills.io），多平台采用 | ✅ 格式已是开放标准，git 历史即归档 |
| MCP 官方 Registry | 无硬依赖（仅元数据对齐） | 无 — 本项目自身即私有注册表 | ✅ 仓库即注册表，git-native |
| npm registry | 包安装 | 缓存与镜像可替代 | ⚠️ 见 3.2 lockfile 策略 |
| GitHub（托管/Pages/Actions/GHCR） | 全链路 CI/CD | 需迁移路径 | ⚠️ 见 3.3 出口策略 |
| Redis（限流） | 可选运行时 | 自动降级内存模式（已实测） | ✅ 软依赖 |
| ioredis | lazy import 可选依赖 | 未安装时自动降级 | ✅ 软依赖 |

### 3.2 供应链三层防线（2026 春季 OSS 事件教训）

```yaml
# 第一层：锁定（lockfile + SHA pin）
pnpm-lock.yaml                     # 唯一安装真相源（--frozen-lockfile 强制）
# GitHub Actions 2026 路线图即将支持 workflow 级 dependencies 锁定
# 当前实践: 第三方 action 全部 pin 到 commit SHA（非 @v4 浮动标签）

# 第二层：Kill Switch（package.json pnpm.overrides）
# 供应链事件发生时 5 分钟内热修复，无需等待上游发版:
"pnpm": {
  "overrides": {
    "typescript": "5.9.3"          # 已实战: 防 TS7 回归
    # "被投毒包": "1.2.3"           # 紧急时在此钉住安全版本
  }
}

# 第三层：门禁（dependency review）
# PR 边界阻断已知漏洞依赖合入（见 roadmap: dependency-review-action）
```

**vendor 参考资产隔离**（本项目 565 告警溯源结论）：

- `agents-hub/`、`tools-hub/`、`skills-hub/community/**`、`_external/` 中的第三方项目**自带 lockfile**，其漏洞与本仓库生产链路无关
- 治理方案：Dependabot config 对上述目录设 `"ignore"` + 漏洞扫描 scoped 到核心 workspace
- **效果**：告警噪声 −99%，真实风险可见度提升

### 3.3 平台出口策略（GitHub 断供预案）

| 能力 | 当前（GitHub） | 出口替代 | 迁移成本 |
| ------ | --------------- | ---------- | ---------- |
| 代码托管 | GitHub | GitLab / Gitea / Forgejo（git bundle 每日冷备已天然支持） | 低（git 是通用协议） |
| CI | GitHub Actions | 自托管 Runner → 全 workflow 兼容；或 Gitea Actions（兼容语法） | 低 |
| Pages | GitHub Pages + 自定义域名 | Cloudflare Pages / Netlify（import repo 即可）/ 自托管 Caddy 指向 `public/` 静态产物 | 低（纯静态） |
| 容器 registry | GHCR | 阿里云 ACR / 自托管 Harbor（镜像 tag 不变，改 registry 前缀） | 低 |
| Secrets | GitHub Secrets | SOPS+age / Vault（文件化密钥，仓库外管理） | 中 |
| npm 发布 | npmjs | 可停发 — 包是私有资产，git tag 即版本真相 | 零 |

> **出口演练建议**：每半年执行一次「断供演习」— 用 git bundle + docker save + 静态站点导出，验证 4 小时内可在任意云厂商重建全套服务。

### 3.4 数据主权设计（已在架构中实现）

1. **资产即文件**：831 技能全部是 git 内纯文本（SKILL.md），无数据库绑定 — 任何编辑器/平台可读
2. **Schema 即契约**：agent-registry/schema.json 声明数据结构，不依赖任何运行时才能理解数据
3. **API 即适配器**：Skill Gateway 是资产的可选 HTTP 皮层，网关挂了资产仍在（`git clone` 即全量备份）
4. **镜像即备份**：GHCR 镜像 + git 仓库 + Pages 静态产物构成三重异地冗余

## 四、新项目复用实施路线（SOP）

基于本蓝图孵化新 Agent 资产项目时，按此顺序执行（每步均有本项目实战验证）：

```
D1  复制工程骨架（turbo + pnpm workspace + tsconfig 链）
    → 验收: pnpm typecheck/lint/test/build 四绿
D2  引入安全中间件包（auth + rate-limit-store + security）
    → 验收: fail-closed 401/403/503 冒烟 + backend 降级头
D3  定义资产 Schema（JSON Schema + 校验脚本）
    → 验收: 校验脚本对存量数据 PASS
D4  接入 CI 门禁（ci.yml + security.yml + pages.yml）
    → 验收: 覆盖率门禁触发 + audit 官方源跑通
D5  部署三件套（Docker 多 target + Pages + 域名）
    → 验收: 冒烟 API 断言全绿 + 自定义域名 200
D6  沉淀会话文档体系（docs/ 四件套模板）
    → 验收: 任意新 AI 导师 10 分钟内上下文恢复
```
