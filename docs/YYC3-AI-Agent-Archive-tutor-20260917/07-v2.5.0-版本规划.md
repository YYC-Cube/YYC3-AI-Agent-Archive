# 📋 v2.5.0 版本规划 — 漏洞清零 + doctor 集成评分

> 主题：**Doctor Integrated Quality Gate**（体检门禁一体化）
> 前置：v2.4.0 Supply-Chain Hardened 已发布（M1–M5 全达成，2026-09-22）
> 规划原则：零新增生产依赖、以实测数据为基、全链路闭环验收

## 一、现状基线（2026-09-23 实测）

### 1.1 漏洞实况：12 项 open 全部集中于单一 manifest

**位置**：`packages/yyc3-i18n/examples/vite-react-zh-cn/pnpm-lock.yaml`（i18n 示例工程，非生产链路）

| # | 包 | 严重度 | 脆弱区间 | 修复版本 |
| --- | ----- | -------- | ---------- | ---------- |
| 1394 | nanoid | **high** | < 3.3.12 | 3.3.12 |
| 1392 | browserslist | **high** | <= 4.28.6 | 4.28.7 |
| 1329 | postcss | **high** | <= 8.5.17 | 8.5.18 |
| 1326 | vite | **high** | <= 6.4.2 | 6.4.3 |
| 1330/1328/1324 | postcss | medium | 各区间 | 8.5.10/8.5.18/8.5.23 |
| 1327/1323 | vite | medium | <= 6.4.2 | 6.4.3 |
| 1322 | esbuild | medium | <= 0.24.2 | 0.25.0 |
| 1450 | baseline-browser-mapping | medium | < 2.11.0 | 2.11.0 |
| 1325 | @babel/core | low | <= 7.29.0 | 7.29.6 |

**关键判断**：

- example 的 `package.json` **已声明** `vite: ^6.4.3`，但 lockfile 是旧解析产物 → 一次 `pnpm install` 重解析即可修复大部分
- 影响面：仅示例工程（不入镜像、不进 CI 构建产物），实际风险 = 低；但告警噪声影响审计观感与 GH 推送提示
- 修复策略：**lockfile 重解析 + 必要时 pnpm overrides 强制**，而非删除 example（保留其文档价值）

### 1.2 doctor 现状

根 [package.json](../../package.json) L34：

```json
"doctor": "node packages/yyc3-cli/bin/yyc3-cli.js skills validate -v && node packages/yyc3-cli/bin/yyc3-cli.js skills dedup -v"
```

- ✅ 已有：validate（frontmatter 校验）+ dedup（四分类报告）
- ❌ 缺失：评分集成（H1 引擎已就绪但未接入）、退出码语义（门禁不可用）、MCP registry 校验步骤

## 二、任务分解

### Task V1: 漏洞清零（P0，~0.5h）

**目标**: 默认分支 Dependabot open 告警 12 → 0
**步骤**:

1. `cd packages/yyc3-i18n/examples/vite-react-zh-cn && pnpm install`（lockfile 重解析，vite/postcss/nanoid 等 direct+transitive 全部升级至已声明区间的新版本）
2. 若重解析后仍有残留（如 lockfile 格式差异）：在 example `package.json` 加 `"pnpm": {"overrides": {...}}` 强制 patched 版本
3. 验证：重跑探查确认 open 归零；`pnpm -C packages/yyc3-i18n/examples/vite-react-zh-cn build` 确认 example 仍可构建
**验收标准**:

- [ ] GH Dependabot 页 open = 0（`gh api .../dependabot/alerts?state=open` 空数组）
- [ ] example 构建/dev 不回归
- [ ] git push 推送提示不再出现 "GitHub found 12 vulnerabilities"

### Task V2: doctor 门禁一体化（P1，~0.5 天）

**目标**: `pnpm doctor` 从「信息输出」升级为「CI 可用的质量门禁」（退出码语义）
**步骤**:

1. 新增 `packages/yyc3-cli/lib/doctor.js`：聚合四检
   - validate（现有）
   - dedup（现有，genuine 组阈值门禁：>3600 时 WARN 不阻断，>4000 阻断——防冗余回潮）
   - score（新增：831 技能全量评分，**均分门禁 ≥78**、D/E 级数量不增长——基线 80 分/A:110/B:503/C:217/D:1/E:0）
   - registry（新增：`node scripts/validate-mcp-registry.mjs` 复用）
2. 评分门禁采用「不回退」策略：对比 `docs/skill-score/score-report.json` 基线，仅当均分下降 >2 分或 E 级新增时 exit 1
3. `package.json` doctor script 更新 + CI ci.yml 增设 `pnpm doctor` 步骤（Test 之后）
**验收标准**:

- [ ] `pnpm doctor` 本地全绿退出 0
- [ ] 人为注入降分技能时 doctor exit 1（负向测试 ≥2 用例）
- [ ] CI 集成后 workflow 全绿
**依赖**: V1（先清漏洞，doctor 输出干净基线）

### Task V3: 评分报告基线固化（P1，~0.25 天）

**目标**: 评分报告随版本演进可追溯
**步骤**:

1. `docs/skill-score/` 增加 `baseline-v2.5.0.json`（快照当前分布）
2. doctor score 检查读 baseline 而非最近报告（避免报告更新即门禁漂移）
**验收标准**:

- [ ] baseline 文件入库 + doctor 引用路径正确
**依赖**: V2

### Task V4: 发布 v2.5.0（P2，~0.5h）

**步骤**:

1. CHANGELOG v2.5.0 节（主题：Doctor Integrated Quality Gate）
2. `package.json` version 2.4.0 → 2.5.0
3. 提交 → tag v2.5.0 → release workflow（三镜像 + 冒烟 8 项 + GHCR）
**验收标准**:

- [ ] release workflow 全绿
- [ ] `pnpm doctor` 在 CI 与本地双环境通过

## 五、风险与应对

| 风险 | 影响 | 应对 |
| ------ | ------ | ------ |
| lockfile 重解析引入 breaking 升级（vite 6→7） | example 构建失败 | lockfile-only 重解析（`pnpm install --lockfile-only`）锁定 semver 区间内版本；构建验证兜底 |
| 评分门禁基线过低/过高 | 门禁形同虚设或误伤 | 采用「不回退」对比策略（对 baseline-v2.5.0），不设绝对阈值 |
| dedup genuine 阈值误判 | 参考资产更新导致阻断 | 阈值放宽至 4000 + 仅 WARN 模式先行一个版本 |
| doctor 全量评分耗时（CI ~60s） | CI 时长增加 | 评分步骤加 turbo cache 或容忍（60s 在可接受范围） |
