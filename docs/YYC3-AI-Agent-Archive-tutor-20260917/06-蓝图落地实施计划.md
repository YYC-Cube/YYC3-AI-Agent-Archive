# 📋 蓝图落地实施计划

> **执行有规划，规划有节点，节点有目标，目标可评估**
> 本计划将 [05-可复用技术与项目蓝图](./05-可复用技术与项目蓝图-全链路生产闭环.md) 第五章 Roadmap 及历史携带项转化为可执行任务流（D1–D8，8 个工作日）。

## 一、总体目标

在 v2.3.0 基线（站点已上线 ai-agent.yyc3.vip）之上，完成蓝图五项增强 + 三项治理携带项，达成：

1. **供应链防线落地**：告警噪声清零、Actions SHA 锁定、PR 依赖门禁
2. **生态接入**：server.json 兼容导出，可被 MCP 官方聚合器消费
3. **智能化**：技能质量评分体系（五维评估的资产维度落地）
4. **运维独立**：dedup/volume/version 收尾 + 断供演习机制化

## 二、阶段划分

| 阶段 | 名称 | 目标 | 交付物 | 时间 | 状态 |
|------|------|------|--------|------|------|
| Phase E | 供应链速赢 | Dependabot 治理 + SHA 锁定 | dependabot.yml + 驳回脚本 + 4 workflows pin | D1 | ⬜ |
| Phase F | PR 门禁 | 依赖变更审查阻断 | dependency-review 接入 ci.yml | D2 | ⬜ |
| Phase G | 生态接入 | server.json 兼容导出 | CLI 子命令 + 静态导出 + Schema 校验 | D3–D4 | ⬜ |

| Phase I | 治理收尾 | 携带项清零 + 演习机制 | B2/C1/C2 + 断供演习 runbook | D8 | ⬜ |

## 三、详细任务分解

### Task E1: Dependabot vendor 治理 ⭐速赢（~1h）

**目标**: 消除 565 条告警噪声（99% 来自 `agents-hub/`、`tools-hub/`、`skills-hub/community/**`、`_external/` 等第三方资产自带 lockfile）
**实施**:
- 新增 `.github/dependabot.yml`：显式注册核心 workspace（`/` + `packages/*`），vendor 目录不注册更新
- 新增脚本 `scripts/dismiss-vendor-alerts.mjs`：按 manifest_path 分组，API 批量驳回 vendor 告警（reason: `tolerated_risk`，附注释「参考资产 lockfile，非生产依赖」）
- 保留 vendor lockfile 原样（维护参考资产完整性，不删除）
**验收标准**:
- [ ] dependabot.yml 合入且 `gh api` 确认 updates 目录仅含核心 workspace
- [ ] 驳回脚本执行后 open alerts 中 vendor 来源清零（核心 yyc3-i18n 12 项保留）
- [ ] 脚本幂等（重复执行 no-op）
**风险点**: Dependabot 无法通过配置屏蔽 dependency graph 告警 → 采用 API 驳回 + 文档化 tolerated risk 清单
**完成标记**: ⬜

### Task E2: 第三方 Actions pin 到 commit SHA ⭐P1（~3h）

**目标**: 4 个 workflow（ci/security/release/pages）所有第三方 `uses:` 从浮动 tag 改为 immutable commit SHA + 版本注释
**实施**: 逐个 action 实时查询最新 SHA；格式 `uses: actions/checkout@<sha> # v7`
**验收标准**:
- [ ] `grep -rE "uses:.*@v[0-9]" .github/workflows/` 零命中
- [ ] 全 workflows 推送后 CI/Security/Pages/Release(trigger tag) 各跑通一次
- [ ] dependabot 已启用 actions 更新（SHA+注释格式可被 Dependabot 自动升级）
**依赖关系**: 无
**完成标记**: ⬜

### Task F1: PR 依赖审查门禁 ⭐P2（~2h）

**目标**: PR 边界阻断已知高危依赖合入（Spring 2026 OSS 事件防线）
**实施**: ci.yml 新增 `dependency-review` job（`fail-on-severity: high` + `retry-on-snapshot: true`），仅 PR 触发
**验收标准**:
- [ ] 门禁 job 合入，正常 PR 通过
- [ ] 构造含高危依赖的试验 PR 验证阻断生效后关闭
**依赖关系**: E2（SHA pin 后再加 job，避免重复 pin）
**完成标记**: ⬜

### Task G1: server.json 兼容导出 ⭐P2（2 天）

**目标**: 对齐 MCP Registry 官方 OpenAPI 规范，让本仓库资产可被官方生态聚合器消费（蓝图 1.2 信号 #2 的蓝海卡位）
**实施**:
- CLI 新增 `yyc3 skills export-mcp`：从 skill/agent 元数据生成 `server.json`（namespace `io.github.yyc-cube/<skill>`，schema pin `2025-12-11`）
- 导出静态目录 `public/registry/`（Pages 自动分发）+ 聚合 API `GET /api/v1/registry/servers`
- CI 增加官方 JSON Schema 校验步骤（防上游 schema 演进漂移）
**验收标准**:
- [ ] 生成产物通过官方 server.schema.json 校验（脚本实测 PASS）
- [ ] CLI 子命令 + ≥10 测试用例，覆盖率门禁不降
- [ ] `https://ai-agent.yyc3.vip/registry/` 可访问至少 1 个 server.json 样例
**依赖关系**: 无（与 F1 并行）
**风险点**: MCP Registry 仍为 preview，schema 可能 breaking → pin 版本 + CI 校验兜底
**完成标记**: ⬜

### Task H1: 技能质量评分体系 ⭐P3（3 天）

**目标**: 五维评估「资产维度」工具化落地（启发自 marketplace 生态 curation 层）
**实施**: CLI 新增 `skills score`，五维加权（满分 100）:
| 维度 | 权重 | 度量 |
|------|------|------|
| 元数据完整度 | 25% | frontmatter 字段齐全性（name/description/version/author…） |
| 文档质量 | 20% | 正文长度、示例数、references 引用 |
| 资产健康 | 25% | scripts 语法可执行、相对引用文件存在 |
| 维护活跃度 | 15% | git log 近 90 天提交/作者数 |
| 安全扫描 | 15% | 危险模式正则命中数（复用 sandbox 模式库） |

输出：单技能 0–100 + A–E 等级；全量 JSON/Markdown 报告集成 `pnpm doctor`
**验收标准**:
- [ ] 831 技能全量评分无崩溃，耗时 < 30s
- [ ] ≥15 测试用例（含边界：空 frontmatter/缺失正文/超长正文）
- [ ] 首份评分报告归档 docs（评分分布统计 + 低分 TOP20 清单）
**依赖关系**: G1（共享元数据读取层可并行开发，报告集成在后）
**完成标记**: ⬜

### Task I1: version 路由口径对齐 ⭐携带项（~0.5h）

**目标**: 消除 `/api/v1/version` 404 与 release 冒烟（`/api/v1/health/version`）双口径
**验收标准**:
- [ ] 冒烟清单与路由表 100% 一致（保留 health/version 单一事实源）
**完成标记**: ⬜

### Task I2: skills 卷生产化 ⭐携带项 P2（~0.5 天）

**目标**: 解决默认 `SKILLS_ROOT_DIR=./skills` 空载（health total=0）
**实施**: 镜像内置技能快照（Dockerfile COPY skills 精简子集）+ 启动时 total=0 输出 WARN
**验收标准**:
- [ ] compose 冒烟 health 返回 total>0
- [ ] release.yml 冒烟 8 项仍全绿
**完成标记**: ⬜

### Task I3: dedup 分类治理 ⭐携带项 P2（~0.5 天）

**目标**: 3716 重复组去噪（蓝图 3.2 vendor 隔离的资产侧呼应）
**实施**: CLI dedup 默认忽略 `coverage/`、`dist/`、`node_modules/`；LICENSE 类白名单；输出「预期重复 vs 待治理」分类报告
**验收标准**:
- [ ] doctor dedup 输出分类统计；待治理清单归档 docs
**完成标记**: ⬜

### Task I4: 断供演习机制化（~1h）

**目标**: 蓝图 3.3「每半年断供演习」从建议变机制
**实施**: 新增 `docs/runbooks/supply-chain-drill.md`（git bundle + docker save + 静态导出三步 runbook）；根 docs 建立演习排期（首次 2027-03）
**验收标准**:
- [ ] runbook 含可复制命令清单与 4 小时重建验收清单
**完成标记**: ⬜
