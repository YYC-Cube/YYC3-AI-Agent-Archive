# YYC³ 微调数据构建规范

## 一、设计目标

本规范定义 YYC³ AI Family 中 Agent 身份固化与能力增强所需的微调数据集构建全流程，覆盖**数据采集、标注规范、数据安全、质量评估、版本管理**五大环节。

| 目标 | 度量指标 |
| ---- | -------- |
| 人设一致性提升 | 微调后人设一致性得分 ≥ 85 分 |
| 指令遵循准确率 | 核心指令遵循率 ≥ 95% |
| 风格稳定性 | 角色语气偏离率 < 5% |
| 幻觉率控制 | 微调后幻觉率 < 3% |

---

## 二、数据采集规范

### 2.1 数据来源

| 数据来源 | 适用场景 | 采集量建议 | 优先级 |
| -------- | -------- | ---------- | ------ |
| **品牌官方文案** | 品牌知识、话术风格 | 500-2000 条 | ★★★★★ |
| **历史优质服务对话** | 交互模式、问题处理 | 1000-5000 条 | ★★★★☆ |
| **行业标准语料** | 领域知识、专业术语 | 2000-10000 条 | ★★★☆☆ |
| **合成指令数据** | 指令多样性增强 | 500-3000 条 | ★★★☆☆ |
| **用户反馈修正** | Bad Case 修复 | 持续积累 | ★★★★★ |

### 2.2 数据格式标准

所有微调数据统一采用以下 JSONL 格式：

**SFT（有监督微调）格式**：
```json
{
  "id": "YYC3-SFT-20260723-001",
  "source": "historical_dialogue",
  "domain": "agent_identity",
  "target_agent": "言启·千行",
  "instruction": "作为YYC³的官方入口Agent，请分析用户需求...",
  "input": "帮我分析一下上个月的运营数据",
  "output": "好的，我已识别到您的数据分析需求，正在调度语枢·万物为您深度解读运营报告...",
  "metadata": {
    "persona_score": 0.95,
    "style_score": 0.92,
    "difficulty": "easy",
    "scenario": "intent_routing"
  }
}
```

**DPO（直接偏好优化）格式**：
```json
{
  "id": "YYC3-DPO-20260723-001",
  "source": "human_feedback",
  "target_agent": "智云·守护",
  "instruction": "请处理以下安全告警...",
  "chosen": "检测到prompt注入攻击，已执行强制拦截...",
  "rejected": "该请求存在风险，但您如果确实需要...",
  "metadata": {
    "rationale": "安全Agent应果断拦截，不妥协",
    "persona_alignment": "chosen更符合安全官冷峻果断的人设"
  }
}
```

## 三、标注规范

### 3.1 标注质量分级

| 等级 | 标准 | 用途 | 采纳策略 |
| ---- | ---- | ---- | -------- |
| **A级(金牌)** | 人设一致+逻辑严谨+风格准确 | 核心训练集 | 100% 采用 |
| **B级(银牌)** | 少数表达不够精准 | 辅助训练集 | 70% 采样 |
| **C级(铜牌)** | 存在轻微风格偏差 | 仅做参考 | 人工修正后采用 |
| **D级(不合格)** | 人设偏离或逻辑错误 | 不采用 | 退回重标 |

### 3.2 标注审核流程

```
标注任务分配
    │
    ▼
┌──────────────────┐     ┌──────────────────┐
│  初标 (标注员)    │     │  抽检 (质检员)    │
│  按规范完成标注   │ ──→ │  20% 随机抽检    │
└──────────────────┘     └────────┬─────────┘
                                  │
                      ┌───────────┴───────────┐
                      ▼                       ▼
              ┌──────────────┐      ┌──────────────────┐
              │ 通过 → 入库   │      │ 不通过 → 退回修改 │
              └──────────────┘      └──────────────────┘
```

### 3.3 数据量基线建议

| 微调类型 | 最低数据量 | 推荐数据量 | 最优数据量 |
| -------- | ---------- | ---------- | ---------- |
| **SFT 风格微调** | 500 条 | 1000-3000 条 | 5000 条 |
| **SFT 知识注入** | 1000 条 | 2000-5000 条 | 10000 条 |
| **DPO 对齐** | 200 条 | 500-1000 条 | 2000 条 |
| **人设增强** | 300 条 | 500-1500 条 | 3000 条 |

## 四、数据安全规范

| 安全维度 | 要求 | 检测手段 |
| -------- | ---- | -------- |
| **脱敏处理** | 所有个人隐私信息必须脱敏（姓名/电话/地址/ID等） | 正则匹配 + 模型检测 |
| **数据分级** | 训练数据按敏感度分为公开/内部/敏感三级 | 自动打标 |
| **版权合规** | 外部语料必须有明确授权或为开源合规数据 | 版权声明检查 |
| **内容审核** | 所有训练数据不得包含违法违规、歧视偏见内容 | 智云·守护安全校验 |
| **数据溯源** | 每条训练数据必须标注来源，支持追溯 | 元数据字段 |

## 五、质量评估体系

### 5.1 评估维度

| 维度 | 指标 | 评估方式 | 目标值 |
| ---- | ---- | -------- | ------ |
| **人设一致性** | 角色身份是否稳定 | 人工评分 + 模型对抗 | ≥ 85/100 |
| **指令遵循** | 是否准确遵循指令要求 | 自动化测试集 | ≥ 95% |
| **风格准确度** | 语气用词是否符合角色 | LLM-as-Judge | ≥ 90% |
| **内容准确度** | 事实性信息是否准确 | 知识库检索对比 | ≥ 98% |
| **反面拒止** | 越界请求是否准确拒绝 | 红队测试 | 100% |

### 5.2 回归测试机制

每次微调迭代前，使用固定的评测集（含 200+ 测试用例）全量跑分：

```
前一次最优模型
    │
    ▼
┌──────────────────────┐
│  新训练版本            │
│  运行回归测试         │
└──────┬───────────────┘
       ▼
┌──────────────────────┐     ┌──────────────────────┐
│  核心指标全部达标?    │ ──→ │ 是 → 进入灰度上线    │
│  (无 regression)     │     └──────────────────────┘
└──────┬───────────────┘
       │ 否
       ▼
┌──────────────────────┐
│  分析回归原因         │
│  修复后重新训练       │
└──────────────────────┘
```

## 六、版本管理与迭代

| 阶段 | 操作 | 审核机制 |
| ---- | ---- | -------- |
| **数据构建** | 采集 → 清洗 → 标注 → 审核入库 | 抽检 + 全量安全扫描 |
| **训练前** | 数据集版本锁定 + 效果基线记录 | 格物·宗师审核 |
| **训练后** | 评测集全量跑分 + 与基线对比 | 自动报告 + 人工确认 |
| **灰度上线** | 10% 流量验证 24h | 核心指标监控 |
| **全量上线** | 100% 流量 | 持续监控 + Bad Case 回流 |
