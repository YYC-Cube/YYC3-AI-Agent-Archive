# YYC³ 多租户隔离架构设计

## 一、设计背景与目标

随着 YYC³ AI Family 进入第三阶段（生态化自进化期），多租户隔离成为必须解决的核心架构问题。本设计目标：

| 目标 | 说明 |
| ---- | ---- |
| **数据安全** | 不同租户的数据严格隔离，禁止跨租户数据访问 |
| **资源公平** | 各租户按配额使用计算资源，防止资源抢占 |
| **性能隔离** | 单个租户的突发流量不影响其他租户的服务质量 |
| **安全独立** | 租户间的安全策略、审计日志独立维护 |
| **管理统一** | 统一的管理面与控制面，支持租户自服务 |

### 2.1 第一层：数据隔离

| 隔离维度 | 实现策略 | 技术选型 |
| -------- | -------- | -------- |
| **数据库隔离** | Schema 级别隔离（同库不同 Schema） | PostgreSQL Schema + Row Level Security |
| **缓存隔离** | Key 前缀 + 独立 Redis DB Index | Redis DB 0-15 分配 |
| **向量库隔离** | Collection 级别隔离 | Qdrant Collection 按租户创建 |
| **对象存储隔离** | Bucket/Prefix 隔离 | MinIO Bucket per tenant |
| **搜索引擎隔离** | Index 级别隔离 | Elasticsearch Index per tenant |

```sql
-- PostgreSQL 行级安全策略示例
CREATE POLICY tenant_isolation ON tenant_data
    USING (tenant_id = current_setting('app.current_tenant')::UUID);
```

### 2.2 第二层：资源隔离

| 资源类型 | 隔离策略 | 配额管理 |
| -------- | -------- | -------- |
| **CPU/内存** | Kubernetes ResourceQuota + LimitRange | 按租户等级分配(基础/专业/企业) |
| **GPU 算力** | 租户独占 GPU 时间片 + 队列调度 | 企业级租户独占 GPU |
| **API 调用** | 租户级 Rate Limiting | 按 SLA 分配 QPS 配额 |
| **存储容量** | 租户级 StorageQuota | 按租户等级分配容量上限 |
| **网络带宽** | 租户级 Bandwidth Limit | 共享带宽池 + 租户上限 |

**弹性扩缩容策略**：
- 非高峰期：闲置资源按需分配给低优先级租户
- 高峰期：保障高优先级租户的 SLA，低优先级租户排队
- 突发需求：支持租户临时申请追加配额，按量计费

### 2.3 第三层：安全隔离

| 安全维度 | 实现策略 | 说明 |
| -------- | -------- | ---- |
| **认证隔离** | 租户级 OIDC/OAuth2 独立 Identity Provider | 租户可对接自有 IdP |
| **授权隔离** | RBAC + 租户角色 | 角色作用域限定在租户内 |
| **网络隔离** | Kubernetes NetworkPolicy + 租户专属 Service | 租户间网络完全隔离 |
| **审计隔离** | 租户独立审计日志流 | 审计日志按租户分区存储 |
| **加密隔离** | 租户独立加密密钥 | 企业级租户支持 BYOK |

## 四、租户分级与配额体系

| 等级 | 典型场景 | 数据隔离 | 资源配额 | 支持 Agent 数 | SLA |
| ---- | -------- | -------- | -------- | ------------- | --- |
| **基础版** | 个人开发者/小团队 | Schema 隔离 | 2C4G, 1000 QPS | 3 | 99.9% |
| **专业版** | 中型企业/部门 | 独立 Schema + 缓存 | 4C8G, 5000 QPS | 6 | 99.95% |
| **企业版** | 大型企业/集团 | 物理隔离 + BYOK | 8C16G+, 20000 QPS | 8 | 99.99% |
