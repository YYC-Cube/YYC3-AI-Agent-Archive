## 二、标准化排版规范体系

### 2.1 文档标头规范（YAML Front Matter）

所有 Markdown 文档 **必须** 包含标准化的 YAML Front Matter 标头，格式如下：

```yaml
---
file: {文件名.md}
description: {文档简要描述（一句话概括定位与价值）}
author: YanYuCloudCube Team <admin@0379.email>
version: v{major}.{minor}.{patch}
created: {YYYY-MM-DD}
updated: {YYYY-MM-DD}
status: {draft | review | stable | deprecated}
tags: [{tag1},{tag2},{tag3}]
category: {architecture | policy | technical | general | tutorial}
language: zh-CN
audience: {target-audience-roles}
complexity: {beginner | intermediate | advanced}
related_docs: {关联文档文件名用逗号分隔}
---
```

**字段规范说明**：

| 字段 | 是否必填 | 规范要求 |
| ---- | -------- | -------- |
| `file` | ✅ 必填 | 文件名必须与磁盘文件名完全一致 |
| `description` | ✅ 必填 | 一句话说明核心定位，控制在 30-60 字 |
| `author` | ✅ 必填 | 统一使用 `YanYuCloudCube Team <admin@0379.email>` |
| `version` | ✅ 必填 | 遵循 SemVer 2.0.0（主版本.次版本.修订号） |
| `created` | ✅ 必填 | 首次创建日期 |
| `updated` | ✅ 必填 | 最近更新日期，须与变更历史最新一致 |
| `status` | ✅ 必填 | 文档状态标识 |
| `tags` | ✅ 必填 | 3-8 个标签，用方括号包裹 |
| `category` | ✅ 必填 | 映射到文档体系分类 |
| `language` | ✅ 必填 | `zh-CN` |
| `audience` | 推荐 | 目标读者角色，多角色用逗号分隔 |
| `complexity` | 推荐 | 文档复杂度等级 |
| `related_docs` | 推荐 | 关联文档文件列表 |

### 2.2 文档排版规范

#### 层级结构规范

```
# 一级标题（文档标题）—— 每文档仅一个
## 二级标题（章标题）
### 三级标题（节标题）
#### 四级标题（子节标题）

规范要求：
- 一级标题：每文档仅一个，与 YAML 中的标题对齐
- 二级标题：使用「一、二、三」中文数字编号 + 中文标题
- 三级标题：使用「1. 2. 3.」阿拉伯数字 + 标题
- 四级标题：使用「###」不加编号
- 层级深度：不超过四级
```

#### 品牌标识尾注规范

每份文档正文结束后、关联文档前，统一使用品牌尾注：

```markdown
---

<div align="center">

**_言启千行代码，语枢万物智能_**

_本文档基于 YYC³ 五高五标五化五维核心机制编制，遵循 YYC³ 团队标准化规范。_

</div>
```

#### 表格规范

| 规范项 | 要求 |
| ------ | ---- |
| 表头格式 | 首行表头使用 `| --- |` 分隔 |
| 对齐方式 | 文本左对齐、数字右对齐、状态居中 |
| 表格前说明 | 表格前需有一句说明性文字 |
| 表格后间距 | 表格后空一行 |

#### 代码块规范

| 规范项 | 要求 |
| ------ | ---- |
| 语言标识 | 必须指定语言（` ```json `、` ```sql `、` ```python ` 等） |
| 块前说明 | 代码块前需有一句说明文字 |
| 行长度 | 每行不超过 100 字符 |
| 嵌套标记 | 避免代码块中出现与包裹标记冲突的内容 |

#### 关联文档与变更历史

每份文档末尾必须包含以下两个章节：

```markdown
## 关联文档

| 文档名称 | 关联关系 | 链接 |
| -------- | -------- | ---- |
| 文档 A | 关系说明 | [链接](./文档A.md) |
| 文档 B | 关系说明 | [链接](./文档B.md) |

---

## 变更历史

| 版本 | 日期 | 变更内容 | 作者 |
| ---- | ---- | -------- | ---- |
| v1.0.0 | YYYY-MM-DD | 初始版本 | YanYuCloudCube Team |
```

### 2.3 文档目录结构规范

#### 目录组织原则

| 原则 | 说明 |
| ---- | ---- |
| **扁平优先** | 目录层级不超过 3 层，避免深层嵌套 |
| **分类独立** | 不同类别的文档放入对应子目录 |
| **单一权威** | 同一主题仅保留一份权威版本，避免重复 |
| **索引引导** | 根目录 `README.md` 作为全局索引 |
| **命名统一** | 文件名遵循 `YYC3-{领域}-{主题}.md` 格式 |

#### 文件命名规范

```
格式：YYC3-{领域分类}-{文档主题}-{细化说明}.md

领域分类规范：
- AI-Family-    : AI Family 家族系列（架构/Agent 等）
- Agent-        : Agent 相关规范
- Skill-        : Skill 相关规范
- Docs-         : 文档体系相关
- {团队通用}    : 团队规范类（按原有命名保持一致）

示例：
✅ YYC3-AI-Family-九层全栈架构.md
✅ YYC3-Agent-系统提示词.md
✅ YYC3-Skill-核心定位与设计原则.md
✅ YYC3-微调数据构建规范.md

❌ 避免：命名过于冗长、中英文混排不一致、无前缀
```

## 九、长期演进方向

### 9.1 文档体系成熟度模型

```
Level 1: 初始级 ─── 文档零散存在，命名不规范，无统一标准
                   ↓
Level 2: 规范级 ─── 文档按规范创建，YAML 标头完善，有 README 索引
                   ↓  ← YYC³ 当前所处阶段
Level 3: 标准级 ─── 交叉引用体系完善，术语统一，格式自动化校验
                   ↓
Level 4: 治理级 ─── 文档纳入 CI/CD，变更与代码同步，自动生成 CHANGELOG
                   ↓
Level 5: 智能级 ─── 基于 RAG 的文档智能问答，文档质量自动度量
```

**YYC³ 当前水平**：Level 2 → Level 3 过渡期，目标在 2 个月内达到 Level 3，6 个月内迈向 Level 4。

### 9.2 四大长期战略方向

| 方向 | 描述 | 预期价值 |
| ---- | ---- | -------- |
| **智能文档助手** | 基于 RAG 构建文档智能问答 Agent，降低文档检索成本 | 开发者效率提升 50%+ |
| **文档质量度量体系** | 建立量化指标（完整度、准确度、时效性、引用密度） | 文档质量可度量、可追踪 |
| **生态化文档共建** | 随 Skill 市场开放，建立文档贡献与审核机制 | 社区共建，生态繁荣 |
| **国际化文档体系** | 核心文档英文版，支持全球化技术社区 | 国际影响力与品牌辐射 |

### 9.3 持续迭代机制

每季度文档评审

    ▼

                         │
