# claude

以下是对这 8 个技术相关术语的详细释义，结合其应用场景和核心作用说明，帮助理解具体含义：

### 1. ui_to_artifact

核心释义：用户界面到成果物的转化 / 关联（“UI” 全称为 “User Interface”，即用户界面，指人与设备 / 软件交互的视觉及操作界面；“artifact” 在技术与设计领域译为 “成果物”，指开发或设计流程中产生的可交付、可复用的产出物）。
应用场景：常见于 UI 设计、软件开发流程中，比如将 Figma 中的 UI 设计稿（界面）转化为可落地的前端代码模块、界面原型文件、设计规范文档等成果物，或建立 UI 元素与对应开发成果物的关联关系，方便团队追溯和管理。

### 2. extract_text_from_screenshot

核心释义：从截图中提取文本（通过 OCR（光学字符识别）技术或图像文本分析算法，识别截图中的文字内容并转化为可编辑、可检索的文本格式）。
应用场景：避免手动录入截图中的文字信息，提升效率，比如从软件界面截图中提取按钮文字、报错提示、数据表格内容，或从纸质文档扫描截图中提取文字以生成电子文档。

### 3. diagnose_error_screenshot

核心释义：诊断错误截图（通过分析包含软件 / 系统错误信息的截图，识别错误类型、定位错误原因、甚至提供解决方案的过程）。
应用场景：常用于技术支持、软件开发调试中，比如用户反馈 “软件闪退” 并附上错误弹窗截图，技术人员通过分析截图中的错误代码、弹窗提示，判断是兼容性问题、代码 bug 还是配置错误。

### 4. understand_technical_diagram

核心释义：理解技术图表（对技术领域专用图表的逻辑结构、组件含义、关联关系进行解读，明确图表所传递的技术信息的过程）。
应用场景：覆盖 IT、工程等领域，比如程序员通过 “系统架构图” 理解各服务模块的调用关系，运维人员通过 “网络拓扑图” 掌握设备连接逻辑，工程师通过 “电路原理图” 了解电路工作原理。

### 5. analyze_data_visualization

核心释义：分析数据可视化（对以图表、图形等可视化形式呈现的数据进行解读，挖掘数据背后的趋势、规律、异常或关联关系的过程）。
应用场景：广泛用于数据分析、业务决策中，比如通过 “销售趋势折线图” 分析某产品季度销量变化，通过 “用户画像饼图” 了解用户年龄分布，通过 “数据仪表盘” 实时监控业务核心指标（如日活、转化率）的异常波动。

### 6. ui_diff_check（UI差异检查）

- **核心功能**：通过技术手段自动对比两个或多个UI界面（如设计稿与实际开发界面、不同版本的界面、不同设备适配的界面），识别视觉元素、布局、样式等维度的差异，并生成差异报告的功能。
- **关键检查维度**：涵盖界面组件位置（如按钮、输入框坐标）、尺寸（宽高）、颜色（RGB值、色号）、字体（类型、大小、字重）、图标/图片一致性，以及动态交互状态（如hover、选中态）的差异。
- **典型应用场景**：
  - 设计稿与开发还原的一致性校验，避免“视觉走样”（如设计稿按钮为圆角，开发成直角）；
  - 软件版本迭代中，防止旧功能UI因代码修改意外变更（如升级版本后，某个页面标题位置偏移）；
  - 多端适配校验（如PC端与移动端UI、不同分辨率屏幕下的界面差异），确保跨场景体验统一。

### 7. analyze_image（图像分析）

- **核心功能**：利用图像识别、计算机视觉等技术，对图像的内容、特征、属性进行提取与解读，输出结构化信息或分析结论的功能，可根据场景聚焦不同分析维度。
- **常见分析方向**：
  - **内容识别**：识别图像中的物体（如“图中有手机、键盘”）、场景（如“办公室场景”）、人物（如人脸识别、姿态判断）、文字（结合OCR提取文本）；
  - **特征分析**：提取图像的色彩分布（如主色调占比）、清晰度（判断是否模糊）、分辨率、尺寸，以及图像质量（如是否有噪点、畸变）；
  - **特定场景分析**：如工业场景中“分析产品图像判断是否有划痕缺陷”、医疗场景中“分析医学影像（X光、CT图）辅助识别病灶”、零售场景中“分析货架图像判断商品陈列是否完整”。
- **核心价值**：将非结构化的图像信息转化为可量化、可利用的数据，支撑自动化判断或决策。

### 8. analyze_video（视频分析）

- **核心功能**：基于计算机视觉、视频处理技术，对视频流（实时视频或录制视频）的帧序列进行逐帧或批量分析，提取动态内容信息、行为逻辑、事件特征，并输出分析结果的功能，本质是“动态图像序列的深度解读”。
- **核心分析能力**：
  - **内容提取**：提取视频中的关键帧（如精彩瞬间、异常画面）、静态图像（截图）、音频轨道，以及视频元数据（时长、分辨率、帧率）；
  - **动态识别与追踪**：识别视频中的运动物体（如行人、车辆），并实时追踪其轨迹（如“追踪某辆车在路口的行驶路径”），同时可识别物体行为（如“行人横穿马路”“车辆变道”）；
  - **事件检测**：自动识别视频中的特定事件（如安防场景中“有人翻越围墙”“物品遗留”，交通场景中“车辆追尾”，直播场景中“画面卡顿、黑场”）；
  - **内容理解**：对视频主题、风格、情感倾向进行分析（如“判断视频为‘产品测评’类内容”“识别视频画面是否存在违规信息”）。
- **典型应用场景**：
  - 安防监控：实时监测异常行为并触发警报；
  - 交通管理：分析车流密度、识别违章行为；
  - 媒体运营：自动剪辑视频精彩片段、检测内容合规性；
  - 工业质检：通过视频实时监测生产线产品是否存在装配缺陷。


你提到的“Claude Code 终端命令”，推测是指 **Anthropic Claude 相关的终端/CLI（命令行界面）工具命令**（例如 Claude 官方或第三方开发的终端客户端、API 调用工具等）。由于 Claude 本身无内置系统终端命令，核心是通过 CLI 工具调用 Claude API 实现对话、代码生成等功能，以下是最常用的 **Claude CLI 工具命令及释义**（以官方推荐的 `claude-cli` 或主流第三方工具为例）：


### 一、核心前提
使用前需先完成：
1. 安装 Claude CLI 工具（通常通过 `pip install claude-cli` 或官方脚本安装）；
2. 配置 Anthropic API Key（通过命令 `claude configure` 录入，API Key 需从 Anthropic 官网申请）。


### 二、常用 Claude 终端命令（CLI）及释义
| 命令格式                                  | 核心功能                                                                 | 补充说明/示例                                                                 |
|-------------------------------------------|--------------------------------------------------------------------------|------------------------------------------------------------------------------|
| `claude configure`                        | 配置 Claude API Key（必填初始化步骤）                                    | 执行后按提示输入 API Key，工具会自动保存配置（默认路径：`~/.claude/config`）  |
| `claude chat`                             | 启动交互式聊天模式（类似终端版 Claude 对话）                              | 直接输入问题/指令，回车发送；输入 `/quit` 退出聊天                            |
| `claude chat -p [prompt]`                 | 非交互式单次提问（直接在命令后带问题，无需进入交互模式）                  | 示例：`claude chat -p "用Python写一个快速排序"`                               |
| `claude chat --file [文件路径]`            | 上传文件并让 Claude 分析/处理（支持文本、代码文件等）                     | 示例：`claude chat --file ./test.py "帮我优化这个Python代码的性能"`           |
| `claude code [问题]`                      | 专注于代码生成/调试（部分工具的快捷命令，等价于指定“代码场景”的 chat）    | 示例：`claude code "写一个Shell脚本批量重命名文件"`                           |
| `claude model [模型名]`                   | 指定使用的 Claude 模型（默认通常是 `claude-3-sonnet`）                    | 支持模型：`claude-3-opus`（最强）、`claude-3-sonnet`（平衡）、`claude-3-haiku`（轻量） |
| `claude temperature [数值]`               | 设置生成内容的随机性（0-1，默认0.7）                                     | 数值越低越精准（如0.2适合代码调试），越高越有创造性（如0.9适合创意写作）      |
| `claude max-tokens [数量]`                | 设置 Claude 单次回复的最大 Token 数（默认通常2048，最大支持4096/8192）    | 示例：`claude chat -p "详细讲解HTTP协议" --max-tokens 4096`                  |
| `claude help`                             | 查看所有命令的帮助文档（含参数说明、示例）                                | 执行后会列出所有支持的命令及可选参数，适合快速查阅                            |
| `claude version`                          | 查看当前 Claude CLI 工具的版本号                                          | 用于确认工具是否为最新版（更新命令通常是 `pip install --upgrade claude-cli`）  |
| `claude clear`                            | 清除本地聊天缓存/配置（谨慎使用，会删除已保存的 API Key 和聊天记录）       | 如需重新配置，可执行该命令后再次运行 `claude configure`                      |


### 三、高频使用示例
1. **交互式代码调试**：
   ```bash
   claude chat --model claude-3-sonnet
   # 进入交互后输入："我这段Java代码报错NullPointerException，帮我找问题：[粘贴代码]"
   ```

2. **批量处理文件**：
   ```bash
   claude chat --file ./data.csv "分析这个CSV文件的数据分布，生成统计报告"
   ```

3. **非交互式快速生成代码**：
   ```bash
   claude code -p "写一个Shell脚本，统计当前目录下所有.log文件的总行数" --temperature 0.3
   ```


### 四、注意事项
1. 若使用的是 **第三方 Claude 终端工具**（如 `anthropic-cli`、`claude-shell` 等），命令格式可能略有差异，建议优先执行 `[工具名] help` 查看官方说明；
2. API Key 需妥善保管，避免泄露（配置后工具会加密存储，无需每次输入）；
3. 免费版 API 有调用次数/Token 限制，超出后需升级付费套餐。
