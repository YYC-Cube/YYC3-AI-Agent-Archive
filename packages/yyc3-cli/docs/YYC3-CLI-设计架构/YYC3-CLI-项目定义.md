# YYC³ 项目定义文档

> **言启象限 | 语枢未来 | 万象归元于云枢 | 深栈智启新纪元**

## 1. 项目概述

### 1.1 项目名称

YYC³ CLI - 云枢命令行界面

### 1.2 项目描述

YYC³ CLI 是下一代智能化 DevOps 命令行工具，基于「五高五标五化」核心理念构建，旨在为 YYC³ 团队提供标准化、规范化、自动化、智能化、可视化的开发运维工具链。

### 1.3 核心理念

基于 **「五高五标五化」** 核心理念：

- **五高**: 高可用、高性能、高安全、高扩展、高可维护
- **五标**: 标准化、规范化、自动化、智能化、可视化
- **五化**: 流程化、文档化、工具化、数字化、生态化

### 1.4 项目定位

- **目标用户**: YYC³ 团队开发人员、DevOps 工程师
- **应用场景**: 项目初始化、开发管理、部署运维、安全监控
- **价值主张**: 简化开发流程、提高工作效率、确保标准化合规

## 2. 目录结构

### 2.1 根目录结构

```
yyc3-management/
├── .clinerules/           # 代码规范规则
├── .git-hooks/            # Git 钩子脚本
├── .github/               # GitHub 配置
├── .husky/                # Husky Git 钩子
├── .trae/                 # Trae 配置
├── .vscode/               # VS Code 配置
├── Mac/                   # macOS 专用脚本
├── YYC3_CLI/              # CLI 工具目录
├── grafana/               # Grafana 监控配置
├── packages/              # NPM 包目录
├── scripts/               # 分类脚本目录
├── API-DOCUMENTATION.md   # API 文档
├── DEPLOYMENT-GUIDE.md    # 部署指南
├── DEVOPS-GUIDE.md        # DevOps 指南
├── Dockerfile             # Docker 构建文件
├── README.md              # 项目说明
├── YYC3团队审核执行标准规范.md # 审核标准
└── yyc3-management.sh     # 系统管理脚本
```

### 2.2 核心目录详解

#### 2.2.1 Mac/ 目录

包含 macOS 专用的脚本和工具，如 FRP 配置、环境设置、服务管理等。

#### 2.2.2 YYC3_CLI/ 目录

CLI 工具的主要实现，包含：

- **k8s/**: Kubernetes 配置文件
- **packages/yyc3-cli/**: CLI 核心包
- **各种管理脚本**: 如 AI 服务、DevOps 工具、知识库等

#### 2.2.3 scripts/ 目录

分类脚本，按功能模块组织：

- **ai/**: AI 相关脚本（自动生成、文档、代码审查等）
- **cleanup/**: 清理脚本（缓存、日志、Docker 等）
- **dev/**: 开发工具脚本（设置、状态、同步等）
- **utils/**: 通用工具脚本（颜色、公共函数等）

#### 2.2.4 packages/ 目录

NPM 包管理，包含 yyc3-cli 核心包。

## 4. 功能模块

### 4.1 项目初始化

- **一键创建项目**: 快速生成符合 YYC³ 标准的项目结构
- **智能模板选择**: 支持 basic/ai/devops 三种模板

- **智能构建系统**: 支持 development/production 模式

### 4.3 部署管理

- **多环境部署**: 支持 dev/staging/prod 环境

### 4.4 安全管理

### 4.5 AI 服务管理

- **AI 代码生成**: 智能生成符合规范的代码
- **AI 代码审查**: 自动化代码质量检查

## 6. 配置管理

### 6.1 全局配置

CLI 使用 `~/.yyc3/config.json` 存储全局配置：

```json
{
  "version": "2.0.0",
  "defaultPort": 3200,
  "defaultTemplate": "basic",
  "deploymentEnvironments": {
    "dev": { "port": 3200, "host": "localhost" },
    "staging": { "port": 3300, "host": "staging.yyc3.com" },
    "prod": { "port": 3400, "host": "app.yyc3.com" }
  },
  "logLevel": "info",
  "autoUpdate": true
}
```

### 6.2 环境变量

| 变量            | 描述         | 默认值                   |
| --------------- | ------------ | ------------------------ |
| `LOG_LEVEL`     | 日志级别     | `info`                   |
| `YYC3_HOME`     | YYC³ 主目录  | `~/.yyc3`                |
| `YYC3_CONFIG`   | 配置文件路径 | `$YYC3_HOME/config.yaml` |
| `YYC3_LOGS`     | 日志目录     | `/var/log/yyc3`          |
| `YYC3_DATA`     | 数据目录     | `/var/lib/yyc3`          |
| `AI_MODELS_DIR` | AI 模型目录  | `/opt/yyc3/models`       |

### 6.3 项目配置

每个项目包含以下配置文件：

- **package.json**: NPM 包配置
- **.env.local**: 本地环境变量
- **.env.docker**: Docker 环境变量
- **docker-compose.yml**: Docker 容器配置

## 7. 部署流程

### 7.1 本地部署

```bash
# 安装依赖
npm install

# 构建项目
npm run build

# 启动服务
./yyc3-management.sh start
```

### 7.2 Docker 部署

```bash
# 构建 Docker 镜像
./build-docker.sh

# 启动容器
docker-compose up -d

# 检查状态
docker-compose ps
```

### 7.3 Kubernetes 部署

```bash
# 应用部署配置
kubectl apply -f YYC3_CLI/k8s/deployment.yaml

# 应用 ingress 配置
kubectl apply -f YYC3_CLI/k8s/ingress.yaml

# 检查部署状态
kubectl get pods
```

### 7.4 CI/CD 流水线

GitHub Actions 流水线包含以下步骤：

1. **代码检查**: ESLint + Prettier
2. **测试运行**: 单元测试 + 集成测试
3. **构建镜像**: Docker 镜像构建
4. **安全扫描**: 敏感信息检测
5. **部署**: 根据分支部署到对应环境

## 9. 开发规范

### 9.1 代码规范

- 遵循 YYC³ 代码风格指南
- 使用 Conventional Commits 提交信息
- 所有代码必须通过 ESLint 检查
- 新功能必须包含测试用例

### 9.2 命名规范

- **项目命名**: `yyc3-[类型]-[名称]`
- **文件命名**: 组件使用 PascalCase，工具使用 camelCase
- **变量命名**: 遵循 camelCase，常量使用 UPPER_SNAKE_CASE
- **函数命名**: 遵循 camelCase，类名使用 PascalCase

### 9.3 文档规范

- 所有文件包含标准文件头注释
- README.md 包含项目概述、安装指南、使用示例
- API 文档完整且最新
- 复杂逻辑包含详细注释

## 14. 贡献指南

### 14.1 开发流程

1. **Fork 仓库**
2. **创建特性分支** (`git checkout -b feature/amazing-feature`)
3. **提交更改** (`git commit -m 'feat: add amazing feature'`)
4. **推送到分支** (`git push origin feature/amazing-feature`)
5. **创建 Pull Request**

### 14.2 代码规范

- 遵循 YYC³ 代码风格指南
- 使用 Conventional Commits 提交信息
- 所有代码必须通过 ESLint 检查
- 新功能必须包含测试用例

### 14.3 提交信息格式

```
<类型>[可选 范围]: <描述>

[可选 主体]

[可选 页脚]
```

**类型**:

- `feat`: 新功能
- `fix`: Bug 修复
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 代码重构
- `test`: 测试相关
- `chore`: 构建或辅助工具变动
- `ci`: CI/CD 相关
- `build`: 构建系统或依赖变动
