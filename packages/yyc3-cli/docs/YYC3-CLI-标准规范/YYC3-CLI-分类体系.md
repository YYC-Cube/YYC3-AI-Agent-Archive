# YYC³ 分类体系设计文档

> 基于「五高五标五化」智能核心机制

## 1. 分类体系设计原则

### 1.1 核心理念

基于 **「五高五标五化」** 核心理念构建：

- **五高**: 高可用、高性能、高安全、高扩展、高可维护
- **五标**: 标准化、规范化、自动化、智能化、可视化
- **五化**: 流程化、文档化、工具化、数字化、生态化

### 1.2 设计原则

- **层级清晰**: 目录层级不超过4级
- **命名规范**: 统一使用 kebab-case 命名格式
- **功能明确**: 每个目录都有明确的功能定位
- **易于维护**: 结构合理，便于后续维护和扩展
- **标准化**: 遵循 YYC³ 团队标准规范

## 3. 命名规范

### 3.1 目录命名规范

- 使用 **kebab-case** 格式（小写字母，单词间用连字符连接）
- 目录名称应简洁明了，反映目录功能
- 避免使用缩写，除非是广泛认可的技术缩写
- 目录名称长度不宜过长，一般不超过20个字符

### 3.2 文件命名规范

- **脚本文件**: `kebab-case.sh`（如：`build-docker.sh`）
- **配置文件**: `kebab-case.config.js`（如：`webpack.config.js`）
- **文档文件**: `kebab-case.md`（如：`api-documentation.md`）
- **代码文件**: 遵循对应语言的命名规范
  - JavaScript/TypeScript: `camelCase.js` 或 `PascalCase.tsx`
  - Python: `snake_case.py`

### 3.3 版本号管理

- 使用语义化版本号格式：`MAJOR.MINOR.PATCH`
- 主版本号（MAJOR）: 重大架构变更
- 次版本号（MINOR）: 新功能和改进
- 补丁版本号（PATCH）: Bug 修复和小改进
- 版本号应在文件名或配置文件中明确标注

## 4. 元数据记录

### 4.1 文件元数据

所有文件应包含以下元数据信息（通过文件头注释或配置文件）：

- **文件名称**: 清晰描述文件功能
- **文件版本**: 语义化版本号
- **创建时间**: 文件创建日期
- **修改时间**: 最近修改日期
- **作者**: 文件作者或维护者
- **描述**: 文件功能的简要描述
- **依赖关系**: 文件依赖的其他文件或模块

### 4.2 目录元数据

每个目录应包含一个 `README.md` 文件，记录以下信息：

- **目录名称**: 目录的完整名称
- **功能描述**: 目录的功能和用途
- **包含内容**: 目录中包含的文件类型和内容
- **使用说明**: 目录的使用方法和注意事项
- **维护者**: 目录的维护者

## 6. 待分类文件处理

### 6.1 待分类目录

创建 `待分类/` 目录，用于临时存放未定义或不属于定义主体的内容。

### 6.2 待分类文件记录

对于存放于 `待分类/` 目录的文件，应记录以下详细信息：

- **文件名称**: 完整文件名称
- **文件类型**: 文件的类型和格式
- **文件大小**: 文件的大小
- **创建时间**: 文件创建日期
- **修改时间**: 最近修改日期
- **内容概要**: 文件内容的简要描述
- **可能的分类**: 可能的分类建议
- **处理建议**: 后续处理的建议

### 6.3 处理流程

1. **识别**：识别未定义或不属于定义主体的内容
2. **记录**：记录待分类文件的详细信息
3. **存放**：将待分类文件存放到 `待分类/` 目录
4. **评估**：定期评估待分类文件，确定最终分类
5. **迁移**：将评估后的文件迁移到适当的分类目录

## 7. 实施步骤

### 7.1 准备阶段

1. **创建分类体系文档**：编写详细的分类体系设计文档
2. **创建目录结构**：根据分类体系创建初始目录结构
3. **制定迁移计划**：制定文件迁移的详细计划

### 7.2 实施阶段

1. **文件分类**：根据分类映射规则对文件进行分类
2. **文件迁移**：将文件迁移到对应的分类目录
3. **元数据更新**：更新文件和目录的元数据信息
4. **命名规范化**：统一文件和目录的命名规范

### 7.3 验证阶段

1. **结构验证**：验证目录结构是否符合设计要求
2. **内容验证**：验证文件是否正确分类
3. **元数据验证**：验证元数据信息是否完整准确
4. **命名验证**：验证命名规范是否统一

### 7.4 维护阶段

1. **定期审查**：定期审查分类体系的有效性
2. **持续优化**：根据实际需求持续优化分类体系
3. **文档更新**：及时更新分类体系文档
4. **培训宣传**：向团队成员宣传分类体系的使用方法
